# PR 003 — Shared conversation definitions

## Change

`Doctor` shares its validated `Program` and `Script` through `Arc`. Machines
share the program; native hosts share the script and allocate their own response
counter vector. Each decomposition has one internal counter index assigned at
parse time. Indices are stable within a compiled script and are not exposed in
traces or provider responses.

The counter advances after selecting a reassembly and before executing its
action, including links, `PRE`, and `NEWKEY`. Memories, variables, arrays,
resources, keyword interning, and trace state remain per-session. Startup still
executes the driver and validates its greeting and input suspension.

`Machine::new` accepts `impl Into<Arc<Program>>`, allowing both existing owned
program calls and shared programs. `Program::clone` retains its existing
semantics. MAD's per-instruction clones, normalization, and release settings
are unchanged.

## Measurement

The baseline is commit `7c6d9de`, before the sharing change. Saved baseline and
candidate generation/completion executables use the pinned Rust
`1.97.0-nightly` (`e8e4541ff`), Cargo's default release settings, and identical
fixtures. Executable hashes, source diff, toolchain details, CPU information,
logs, and run order are retained in `target/benchmarks/pr003/`.

Both variants are pinned to logical CPU 16 on the local i9-14900K. Its recorded
governor is `performance`; its sibling group contains only CPU 16. Criterion
uses its existing 50 samples, three-second warmup, and ten-second measurement.
Three independent pairs run in baseline/candidate, candidate/baseline, then
baseline/candidate order. Compilation and allocation profiling finish before
timing starts.

Named estimates are saved in
`target/criterion/**/pr003-{baseline,candidate}-{1,2,3}/estimates.json`.
Run preserved executables with `--bench`: without that flag, Criterion runs
fixture checks instead of measurements. For example:

```sh
taskset -c 16 target/benchmarks/pr003/baseline/generation --bench --noplot --save-baseline pr003-baseline-1
taskset -c 16 target/benchmarks/pr003/candidate/generation --bench --noplot --save-baseline pr003-candidate-1
```

Results are elapsed time, not measured CPU/request. The host has reported CPU
instability, so local estimates are provisional. A stable-host HTTP baseline
and CPU/request comparison remain necessary before claiming deployment gains.

## Results

All three pairs completed without crashes. Every measured runtime case improved
in each pair; compile time remained effectively unchanged. Startup elapsed time
fell by 87.7–88.0%, short ASCII completion by 76.9–77.4%, and 100-turn ASCII
completion by 2.6–4.3%. Sharing removes a large fixed startup cost; it does not
remove replay or per-instruction work.

## Allocation profile

Heaptrack was obtained temporarily from the repository's pinned nixpkgs revision;
it is not a project dependency. Both saved generation executables were profiled
separately on CPU 16 with `--bench eliza/session --profile-time 5`.

The baseline session path allocates while cloning keyword tables and
decomposition/reassembly vectors. These definition-copy paths disappear in the
candidate. Keyword interning and MAD instruction execution still allocate.
Sharing is also verified with pointer-identity and conversation-isolation tests.

The processes complete different iteration counts under profiler overhead.
Their total allocation counts are not allocations per session and must not be
compared as such. Raw profiles are `*-profiled.heaptrack.zst`; reports preserve
full Rust type names in `*-allocations.txt`.

## Validation

`CARGO_INCREMENTAL=0 CARGO_BUILD_JOBS=1 just ok` passed, including workspace
tests, HTTP contracts, Clippy, and Dylint. `just bench-smoke` passed all 68
generation cases and 46 HTTP load points without failures or dropped arrivals.

New coverage verifies shared allocation identity, independent machine storage,
fresh session counters, and session lifetime after dropping doctors. Interleaved
conversations match independently compiled reference sessions in both response
text and trace, exercising rotation, memory, fallback, links, `PRE`, and
`NEWKEY`.
