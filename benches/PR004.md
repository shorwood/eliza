# PR 004 — Bounded input normalization

## Change

The provider input adapter now builds its historical terminal record in one
bounded pass. It allocates at most one output string, preserves the existing
character mapping, collapses separators, and stops when 72 ASCII columns have
been emitted. A separator at column 72 remains part of the record when a word
follows it; trailing separators remain omitted.

Full-request character limits and prompt token accounting still inspect the
original input. Long discarded prefixes still require scanning to find retained
characters. The optimization avoids intermediate normalized strings, the word
vector, the joined string, and scanning suffixes after the record fills.

Public APIs, generation, trace rendering, compiler settings, and dependencies
are unchanged. Benchmark code stays in this workspace crate and imports the
private production adapter without making it public or copying its logic.

## Measurement

The production baseline is `d340032`, including shared definitions and borrowed
MAD instructions. The final benchmark harness is commit `d7878cd`; the candidate
implementation is `870fd36`. Both saved executables use that same harness,
fixtures, lockfile, pinned Rust `1.97.0-nightly` (`e8e4541ff`), and Cargo release
defaults. Compiler details, machine information, executable hashes, source diff,
logs, and run order are retained in `target/benchmarks/pr004/`.

Measurements run on logical CPU 16 of the local i9-14900K, with the recorded
`performance` governor and no SMT sibling. Criterion uses 50 samples,
three-second warmup, and ten-second measurement. Three independent pairs
alternate baseline/candidate, candidate/baseline, then baseline/candidate.
Compilation, validation, and allocation profiling finish before timing starts.

The six helper cases cover short ASCII, Unicode, a separator at column 72,
long discarded prefixes/suffixes, and entirely discarded input. The prefix case
prepends 4,096 U+2003 spaces to `I need help`. The suffix case appends 2,048
copies of ` —` to a complete 72-column record. Completion adds those two inputs
at one user turn and compares existing ASCII/Unicode cases at 1 and 100 turns.
Long inputs fit the configured 8,000-character request limit.

Helper fixture construction and output checks are outside timing. Helper timing
includes output allocation and destruction. Completion request construction is
batched outside timing; completion includes validation, replay, accounting, and
request destruction, with returned response destruction outside timing.
The shared doctor is initialized before measurement.

Named estimates remain in
`target/criterion/**/pr004-{baseline,candidate}-{1,2,3}/estimates.json`.
Saved executables require `--bench` to measure and `--exact` to select one case:

```sh
taskset -c 16 target/benchmarks/pr004/baseline/completion --bench --exact normalization/long_suffix --noplot --save-baseline pr004-baseline-1
taskset -c 16 target/benchmarks/pr004/candidate/completion --bench --exact normalization/long_suffix --noplot --save-baseline pr004-candidate-1
```

Raw estimates and intervals remain in the saved `estimates.json` files.
`target/benchmarks/pr004/summary.json` records these comparisons, including
individual run means and intervals.

Individual 95% bootstrap intervals
describe within-run sampling uncertainty, not host stability.

The measured gain is largest for suffix-heavy input. Short one-turn completions
improve modestly, while 100-turn completions improve by 3.1–4.3% across the
paired means. With identical behavior and no paired mean regression in the
focused matrix, the bounded adapter is retained.

The host has reported CPU instability, so these elapsed-time estimates remain
provisional. They do not establish CPU/request or HTTP concurrency capacity;
those comparisons remain deferred to stable hardware. Full-input validation and
accounting still contribute to long-request completion costs.

## Allocation profile

Both saved executables were profiled separately on CPU 16 with Heaptrack and
`--bench --exact normalization/long_suffix --profile-time 5`. The profiler was
reused from the temporary pinned Nix package obtained for PR 003; it adds no
project dependency.

The baseline's filtered allocation stacks include intermediate string
collection/growth and the word vector. Its adapter also allocates a joined
string. The candidate's complete
filtered graph contains only the output allocation directly in `input_record`;
those intermediate allocation paths disappear.

Raw profiles are `*-profiled.zst`; filtered reports and complete allocation
stacks are `*-allocations.txt` and `*-allocations.folded`. Iteration counts differ
under profiler overhead, so total allocation counts are not allocations per
operation and must not be compared directly.

## Validation

`CARGO_INCREMENTAL=0 CARGO_BUILD_JOBS=1 just ok` passed, including workspace
tests, HTTP contracts, Clippy, and Dylint. `just bench-smoke` passed all 76
generation cases and 46 HTTP load points without failures or dropped arrivals.

New tests compare against the original adapter over all ASCII characters and
200 deterministic mixed-fragment inputs, pin punctuation, Unicode, whitespace,
long prefixes/suffixes, and 71/72/73-column boundaries. The completion regression
checks identical answer/trace with appended content, full-input limit rejection,
and prompt usage including words beyond the retained record.
