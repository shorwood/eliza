# PR 007 — Reuse MAD scalar keys

## Change

`Machine::write` now updates an existing scalar through a borrowed `get_mut`
lookup. It clones the variable name only when inserting a previously absent
scalar. Array writes, loop initialization/advancement, direct labels, `RETURN`,
and public interfaces are unchanged.

Repeated assignments, cooperative input writes, and native argument writeback
share this path. First insertion performs a lookup before insertion, so session
startup is measured alongside steady generation to check that tradeoff.

## Measurement

The baseline is commit `111c60f`, including shared definitions, borrowed MAD
instructions, and bounded provider normalization. The candidate implementation
is `dc3e23d`. Saved baseline and candidate
executables use identical benchmark code, fixtures, lockfile, pinned Rust
`1.97.0-nightly` (`e8e4541ff`), and Cargo release defaults. Executable hashes,
source diff, toolchain, CPU details, build logs, and run order remain in
`target/benchmarks/pr007/`.

Five cases compare session startup, keyword turns, 100-turn ELIZA replay, and
100-turn ASCII/Unicode completions. They use the existing timing boundaries
documented in the [benchmark README](README.md#generation).

Both variants run on logical CPU 16 of the local i9-14900K, with the recorded
`performance` governor and no SMT sibling. Criterion uses 50 samples,
three-second warmup, and ten-second measurement. Three independent pairs
alternate baseline/candidate, candidate/baseline, then baseline/candidate.
Compilation, validation, and allocation profiling finish before timing starts.

Named estimates remain in
`target/criterion/**/pr007-{baseline,candidate}-{1,2,3}/estimates.json`.
Saved executables require `--bench` and `--exact` for focused measurement:

```sh
taskset -c 16 target/benchmarks/pr007/baseline/generation --bench --exact eliza/replay/100 --noplot --save-baseline pr007-baseline-1
taskset -c 16 target/benchmarks/pr007/candidate/generation --bench --exact eliza/replay/100 --noplot --save-baseline pr007-candidate-1
```

Raw estimates and intervals remain in the saved `estimates.json` files.
`target/benchmarks/pr007/summary.json` records the comparison summary and
individual run means/intervals. These intervals describe within-run sampling
uncertainty, not host stability.

The measured steady-state improvements satisfy the acceptance rule. Startup
variation is small and does not consistently regress across these pairs; it is
not evidence of a startup improvement. The scalar overwrite change is retained.

The acceptance rule requires improvement in all three replay pairs and at least
one completion case, with no benchmark regressing in all three pairs.

These are elapsed-time measurements, not CPU/request. The host has reported
CPU instability, so estimates remain provisional. HTTP capacity and CPU/request
comparisons remain deferred to stable hardware.

## Allocation profile

Both saved generation executables are profiled separately on CPU 16 using
Heaptrack and `--bench --exact eliza/replay/100 --test`. Criterion's test mode
executes one selected replay iteration. The harness also performs its existing
fixture checks; allocation counts cover the complete matching invocation,
including those checks and initialization, rather than an isolated replay.

Across the matching fixed invocations, allocation stacks through scalar writes
and `String::clone` contain 5,544 allocation calls in the baseline and 96 in the
candidate, a 98.3% reduction at that path. Remaining key clones are consistent
with first insertions. The production overwrite branch performs no name clone.
These counts include fixture checks and initialization; they are not allocations
per request or per isolated 100-turn replay.

Raw profiles are `*-fixed.zst`; filtered reports and complete allocation stacks
are `*-allocations.txt` and `*-allocations.folded`. The temporary profiler package
uses the project's pinned Nixpkgs revision; no project dependency or
additional allocation-counting harness is introduced.

## Validation

`CARGO_INCREMENTAL=0 CARGO_BUILD_JOBS=1 just ok` passed, including workspace
tests, HTTP contracts, Clippy, and Dylint. `just bench-smoke` passed all 76
generation cases and 46 HTTP load points without failures or dropped arrivals.

The initial quality run stopped on a Rust compiler SIGSEGV while compiling
Criterion. An unchanged retry passed tests and Clippy, then identified a test
loop lint; that loop was replaced with explicit output assertions. The final
full quality run passed. The original crash log is retained as
`target/benchmarks/pr007/quality-first-attempt.log`; its cause is unconfirmed.

New behavioral tests cover default-zero reads, first assignment, repeated
assignment, cooperative input overwrite, and native writeback creating an
absent scalar. Existing scalar/array native calls, loops, budget handling,
machine isolation, conversations, traces, and HTTP contracts remain unchanged.
