# PR 002 — Borrowed MAD instructions

## Change

`Machine::run` clones the shared `Arc<Program>` once after its halted and
pending-input guards. It borrows each instruction from that local handle and
passes the reference to `execute`, removing the deep clone on every interpreter
step. Public interfaces, program-counter advancement, loop advancement,
cooperative events, and instruction limits keep their existing behavior.

Pending input destinations, emitted comments, retained loop state, and error
locations still own the data they need. Loop-frame cloning, label resolution,
normalization, compiler settings, and dependencies are unchanged.

## Measurement

The baseline is commit `376ae15`, including PR 003's shared definitions. Saved
baseline and candidate executables use the same pinned Rust
`1.97.0-nightly` (`e8e4541ff`), Cargo release defaults, and fixtures. Compiler
details, executable hashes, source diff, CPU information, logs, and run order
are retained in `target/benchmarks/pr002/`.

The focused cases are `eliza/turn/keyword`, `eliza/replay/100`, and
`completion/ascii/100`. Both variants run on logical CPU 16 of the local
i9-14900K, with the recorded `performance` governor and no SMT sibling.
Criterion uses 50 samples, three-second warmup, and ten-second measurement.
Three pairs alternate baseline/candidate, candidate/baseline, then
baseline/candidate. Compilation and profiling finish before timing starts.

Named estimates are saved in
`target/criterion/**/pr002-{baseline,candidate}-{1,2,3}/estimates.json`.
Saved executables need `--bench` to measure and `--exact` to select one case:

```sh
taskset -c 16 target/benchmarks/pr002/baseline/generation --bench --exact eliza/turn/keyword --noplot --save-baseline pr002-baseline-1
taskset -c 16 target/benchmarks/pr002/candidate/generation --bench --exact eliza/turn/keyword --noplot --save-baseline pr002-candidate-1
```

Results are elapsed time, not CPU/request. The host has reported CPU instability,
so estimates remain provisional. Full HTTP capacity and CPU/request comparison
are deferred to a stable host. The focused matrix does not establish performance
across every generation workload.

## Results

All three pairs completed without crashes. Every focused case improved in each
pair. Keyword-turn elapsed time fell by 41.0–42.7%, 100-turn replay by
42.7–44.6%, and 100-turn ASCII completion by 40.6–42.2%.

Times below are the median of three independent Criterion mean estimates, in
microseconds. Reductions are the minimum and maximum computed from each pair's
means, not confidence intervals. Samples and cases are not pooled.

| Case | Baseline µs | Candidate µs | Paired time reduction |
| --- | ---: | ---: | ---: |
| `eliza/turn/keyword` | 10.82 | 6.29 | 41.0–42.7% |
| `eliza/replay/100` | 1083.64 | 603.54 | 42.7–44.6% |
| `completion/ascii/100` | 1116.30 | 648.30 | 40.6–42.2% |

session startup and teardown. See [timing boundaries](README.md#generation).

## Allocation profile

Both saved generation executables were profiled separately on CPU 16 with
Heaptrack and `--bench --exact eliza/replay/100 --profile-time 5`. The profiler
was reused from the temporary pinned Nix package obtained for PR 003; it adds
no project dependency.

The baseline contains allocation stacks through `Instruction::clone` during
MAD execution. No such stacks remain in the candidate's complete filtered
allocation graph. Remaining allocations include native arguments, mutable
machine storage, loop frames, and conversation resources.

Raw profiles are `*-profiled.heaptrack.zst`; reports and complete allocation
stacks are `*-allocations.txt` and `*-allocations.folded`. Processes execute
different iteration counts under profiler overhead, so their total allocation
counts must not be interpreted as allocations per operation.

## Validation

`CARGO_INCREMENTAL=0 CARGO_BUILD_JOBS=1 just ok` passed, including workspace
tests, HTTP contracts, Clippy, and Dylint. `just bench-smoke` passed all 68
generation cases and 46 HTTP load points without failures or dropped arrivals.

New tests verify that emitted comments and error locations outlive their
machine/program, budget exhaustion identifies the next instruction and allows
resumption, and native calls write back scalar and array arguments. Existing
cooperative I/O, transfers, loops, machine/session isolation, historical
conversation, and trace tests remain green.
