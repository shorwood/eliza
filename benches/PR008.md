# PR 008 — Borrow direct MAD jump labels

## Change

`Machine::resolve_target` uses `Cow<str>` to borrow direct label names for
successful lookups. Computed targets still evaluate their index once and format
an owned `BASE(index)` label. A failed lookup converts the label into owned
diagnostic storage, preserving its lifetime beyond the target and machine.

Public interfaces, transfer and loop behavior, program-counter ordering,
storage, compiler settings, and dependencies are unchanged. Benchmark code is
unchanged and stays in the existing workspace crate.

## Measurement

The baseline is commit `573960f`, including the previous scalar-key reuse
optimization. The candidate implementation is `7a6963e`.
Saved baseline and candidate executables use identical benchmark
code, fixtures, lockfile, pinned Rust `1.97.0-nightly` (`e8e4541ff`), and Cargo
release defaults. Source diff, executable hashes, build logs, toolchain and
environment details, CPU information, and run order remain in
`target/benchmarks/pr008/`.

Six existing cases compare session startup, keyword/fallback turns, 100-turn
ELIZA replay, and 100-turn ASCII/Unicode completions. Timing boundaries are
documented in the [benchmark README](README.md#generation).

Both variants run on logical CPU 16 of the local i9-14900K, with the recorded
`performance` governor and no SMT sibling. Criterion uses 50 samples,
three-second warmup, and ten-second measurement. Three independent pairs
alternate baseline/candidate, candidate/baseline, then baseline/candidate.
Compilation, validation, and allocation profiling finish before timing starts.

Named estimates remain in
`target/criterion/**/pr008-{baseline,candidate}-{1,2,3}/estimates.json`.
Saved executables require `--bench` and `--exact` for focused measurement:

```sh
taskset -c 16 target/benchmarks/pr008/baseline/generation --bench --exact eliza/replay/100 --noplot --save-baseline pr008-baseline-1
taskset -c 16 target/benchmarks/pr008/candidate/generation --bench --exact eliza/replay/100 --noplot --save-baseline pr008-candidate-1
```

`target/benchmarks/pr008/summary.json` records the comparison summary and
individual run means/intervals. These intervals describe within-run sampling
uncertainty, not host stability.

Replay and Unicode completion improve in all three pairs. ASCII completion and
startup have mixed results. Those outcomes satisfy the acceptance rule, with
no benchmark consistently regressing. The borrowed direct-label change is retained.

The acceptance rule requires improvement in all three replay pairs and at least
one completion case, with no benchmark regressing in all three pairs.

These are elapsed-time measurements, not CPU/request. The host has reported CPU
instability, so estimates remain provisional. HTTP capacity and CPU/request
comparisons remain deferred to stable hardware.

## Allocation profile

Both saved generation executables are profiled separately on CPU 16 using
Heaptrack and `--bench --exact eliza/replay/100 --test`. Criterion's test mode
executes one selected replay iteration. Existing fixture checks also execute,
so allocation counts cover the complete matching invocation rather than an
isolated replay.

The baseline records 1,396 allocation calls through `resolve_target`, all on
`String::clone` stacks. The candidate records zero allocation calls through
that resolver in the matching workload. Direct-label clone allocations disappear.
Computed formatting and missing-target diagnostics retain their owned storage;
their semantics are verified separately by the unit tests.

Raw profiles are `*-fixed.zst`; filtered reports and complete allocation stacks
are `*-allocations.txt` and `*-allocations.folded`. The temporary profiler
package uses the project's pinned Nixpkgs revision and adds no project dependency.

## Validation

`CARGO_INCREMENTAL=0 CARGO_BUILD_JOBS=1 just ok` passed, including workspace
tests, HTTP contracts, Clippy, and Dylint. `just bench-smoke` passed all 76
generation cases and 46 HTTP load points without failures or dropped arrivals.

New tests verify that mutating computed indices evaluate exactly once, missing
computed targets retain their exact label and source module/line after the
machine is dropped, and direct lookup errors outlive their borrowed target and
machine. The private resolver test avoids modifying linked-program invariants.
Existing transfer, loop, budget, machine/session isolation, conversation, trace,
and HTTP tests retain their behavior.
